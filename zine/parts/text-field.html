Issue 01 · Forms · p.06

Text fieldText field

Labelled input with helper text and an error state wired up with aria-describedby.

Why it works: Always use a visible <label>; placeholders vanish while typing. Link hints and errors with aria-describedby and flag errors with aria-invalid.

Try it:
Receipt: axe clean · contrast 5.73:1 · 2 tab stops · RTL ✓ · long text ✓
  • PASS axe, WCAG 2.1 A and AA: no violations in light or dark (15 rules passed).
  • PASS Tightest text contrast 5.73:1, where 4.5:1 is needed (light).
  • PASS Still passes contrast with tokens fitted to a yellow brand colour.
  • PASS Right-to-left with Arabic sample text fits a 390px phone.
  • PASS Every string 40% longer still fits a 390px phone.
  • PASS Only short hover and focus transitions (under 300ms).

Tab order

  1. textbox "Email":
  2. textbox "Password" [invalid]

What assistive tech is given

- text: Email
- textbox "Email":
  - /placeholder: you@example.com
- paragraph: We’ll never share your email.
- text: Password
- textbox "Password" [invalid]
- paragraph: Use at least 8 characters.

Automated checks in CI (axe in Chromium, reduced motion on). They catch a lot, not everything: still try it with a screen reader.

See it in the zine npx -y tearsheet add text-field

Needs the shared tokens.css once per project.
