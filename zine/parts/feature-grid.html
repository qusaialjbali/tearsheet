Feature gridFeature grid

Six features as short, scannable blocks, each leading with what it does for the reader.

Why it works: Write the heading as the benefit (“Settle in one tap”), not the feature name. Six is a comfortable maximum; more and nobody reads them.

Try it:
Receipt: axe clean · contrast 6.7:1 · 0 tab stops · RTL ✓ · long text ✓
  • PASS axe, WCAG 2.1 A and AA: no violations in light or dark (9 rules passed).
  • PASS Tightest text contrast 6.7:1, where 4.5:1 is needed (light).
  • PASS Still passes contrast with tokens fitted to a yellow brand colour.
  • PASS Right-to-left with Arabic sample text fits a 390px phone.
  • PASS Every string 40% longer still fits a 390px phone.
  • PASS No motion.

Tab order: nothing here takes focus (it is content, not controls).

What assistive tech is given

- heading "Everything a shared budget needs" [level=2]
- list:
  - listitem:
    - heading "Settle in one tap" [level=3]
    - paragraph: Pocketsplit finds the fewest payments to square everyone up.
  - listitem:
    - heading "Split any way" [level=3]
    - paragraph: Evenly, by shares, by exact amounts or by percentage.
  - listitem:
    - heading "Any currency" [level=3]
    - paragraph: Spend in yen, settle in euros, at the day’s real rate.
  - listitem:
    - heading "Snap the receipt" [level=3]
    - paragraph: Photos are attached to the expense, so nobody argues later.
  - listitem:
    - heading "Works offline" [level=3]
    - paragraph: Add expenses on the mountain; they sync when you are back.
  - listitem:
    - heading "Private by default" [level=3]
    - paragraph: Only people in a group can see it. No ads, ever.

Automated checks in CI (axe in Chromium, reduced motion on). They catch a lot, not everything: still try it with a screen reader.

See it in the zine npx -y tearsheet add feature-grid

Needs the shared tokens.css once per project.
