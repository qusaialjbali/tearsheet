ChangelogChangelog

Release notes grouped by date, each change tagged New, Improved or Fixed.

Why it works: Lead with what changed for the user, not the ticket title. Dates are machine-readable <time> elements so feeds and search engines understand them.

Try it:
Receipt: axe clean · contrast 4.79:1 · 0 tab stops · RTL ✓ · long text ✓
  • PASS axe, WCAG 2.1 A and AA: no violations in light or dark (8 rules passed).
  • PASS Tightest text contrast 4.79:1, where 4.5:1 is needed (light).
  • PASS Still passes contrast with tokens fitted to a yellow brand colour.
  • PASS Right-to-left with Arabic sample text fits a 390px phone.
  • PASS Every string 40% longer still fits a 390px phone.
  • PASS No motion.

Tab order: nothing here takes focus (it is content, not controls).

What assistive tech is given

- heading "What’s new" [level=2]
- article:
  - time: 20 Nov 2026
  - heading "Version 3.2" [level=3]
  - list:
    - listitem: New Split by percentage, not just shares.
    - listitem: Improved Receipts load twice as fast on slow connections.
    - listitem: Fixed Totals no longer round the wrong way in yen.
- article:
  - time: 28 Oct 2026
  - heading "Version 3.1" [level=3]
  - list:
    - listitem: New Dark mode follows your system setting.
    - listitem: Fixed Guests can now attach photos.

Automated checks in CI (axe in Chromium, reduced motion on). They catch a lot, not everything: still try it with a screen reader.

See it in the zine npx -y tearsheet add changelog

Needs the shared tokens.css once per project.
